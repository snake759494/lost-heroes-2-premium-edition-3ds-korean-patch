# 기술 문서

## ROM 구조
- 원본은 복호화된 NCSD(`.3ds`)이고 NCCH의 NoCrypto 플래그(0x18F 비트 2)가 켜져 있습니다.
- `tools/ctr.py`: NCSD → NCCH → ExeFS / RomFS 추출. `tools/build.py`: RomFS 파일 교체 후 IVFC 해시 트리·NCCH 헤더·NCSD 파티션 표 재작성.
- 실행 코드(`.code`)는 BLZ 압축(`tools/codeblz.py`)이며 이 패치에서는 수정하지 않습니다.

## 압축·아카이브
- `*.cmp`: `COMP` + LZ11(0x11) 스트림(`tools/lz11.py` 해제). 다시 넣을 때는 실제 LZ11 압축(`tools/lz11c`, C#)으로 원본과 비슷한 크기를 유지합니다. 리터럴만으로 저장하면 커진 파일들 때문에 게임이 불안정해질 수 있습니다.
- `*_pk.cmp`: 압축을 풀면 `2NBF` 팩. 헤더 `[u32 개수, u32 데이터 시작, u32 0x10]` + 엔트리 0x8C바이트 `[이름 0x80, u32 상대 오프셋, u32 ?, u32 크기]`, 데이터는 16바이트 정렬(`tools/nbf.py`).
- **게임은 RomFS 단독 파일보다 팩 안 사본을 읽습니다.** 대사 mbb(약 650팩), 폰트(`Graph/STARTUP_pk.cmp` 안 `Font/Font14.tpc`·`Font10.tpc`) 모두 팩 사본까지 교체해야 반영됩니다. 팩 안 mbb는 경로 없는 이름(`DungeonMess.mbb` 등)도 있어, 이름이 아니라 내용(문자열)으로 매칭해 번역합니다.

## 텍스트 (mbb)
- `TBB1` 헤더 `[u32 0x10, u32 표 개수, u32 전체 크기]` + 표 오프셋. 각 표 `MTBL` `[u32 0x10, u32 크기, u32 개수, u32 0]` + 문자열 오프셋(표+0x10 기준, 0이면 없음) + 16바이트 정렬 문자열(`tools/mbb2.py`, 무변경 시 대부분 바이트 단위 동일).
- 문자열은 u16 배열, 0 종료. 값 = **글리프 번호 + 1**. 0x8001 줄바꿈, 0x8002 페이지, 0x8004/0x8005 색 강조, 0x806D 등 0x80xx는 변수(이름·숫자)이고 뒤에 값 1(전각 공백)이 자리 길이만큼 붙습니다.
- **띄어쓰기를 값 1로 넣으면 이벤트 진행 중 게임이 멈춥니다**(변수 자리 채움으로 해석). 한글 띄어쓰기에는 별도의 빈 글리프 슬롯을 씁니다.
- 실행 코드에 문자→글리프 표가 없어(글리프 순서는 게임 전용) 폰트 그림을 일본어 글꼴로 렌더링한 후보와 템플릿 매칭해 원문을 복원했습니다(`tools/glyphmatch.py`). 한자 일부는 비슷한 글자로 오인식되어 번역 시 문맥으로 보정했습니다.
- 번역은 대사창 한 줄 약 24자, 원문 줄 수 이하로 맞췄습니다(`tools/check.py`). 렌더링은 고정폭입니다.

## 폰트
- `GFPT` 헤더 + `CTPK` 텍스처(A4). Font14: 256×512 ×5장, 14×16 칸 18열. Font10: 256×512 ×3장, 12×12 칸 21열. 두 폰트는 같은 글리프 번호를 씁니다(`tools/gfpt.py`, `tools/tex.py`).
- 영숫자·기호 칸(0~63, 233~362)은 원본 글리프를 유지하고, 한자·가나 칸에 한글 1,246자를 다시 그렸습니다(`tools/mkpatch.py`, `tools/hfont.py`). 반각 `!`는 233번(전각 느낌표) 칸을 씁니다(328번은 `/` 모양 글리프).
- Font10은 화면에서 칸의 마지막 줄이 반쯤 그려지고 아래 칸 첫 줄이 번져 들어오므로, 한글을 1~10행 안에 그렸습니다.
- 스태프롤: `Font/FontStaff.cmp`(15×16 칸, 17열)와 `Table/StaffRoll/*.mbb`(값 = FontStaff 칸 번호 + 1)를 함께 재구성합니다.

## 그림 글자(텍스처)
- 팩 안 `*.tpc`(GFPT + CTPK). CTPK 엔트리 `[이름 오프셋, 크기, 데이터 오프셋, 포맷, u16 폭, u16 높이, ...]`, 포맷 0=RGBA8, 2=RGBA5551, 4=RGBA4, 8=A8, 11=A4, 12/13=ETC1/ETC1A4(`tools/ctpk.py`, 디코더 `tools/texdec.py`, 인코더 `tools/texenc.py` — 원본 왕복 시 바이트 단위 동일).
- 대상 찾기: UI 계열 팩의 텍스처를 PNG로 풀어 Windows 일본어 OCR(`tools/ocr`)로 검출. 캐릭터 이름판(BAT_char·BAT_result_char·CMN_CAMP_top)은 전부 검사했습니다.
- 편집: 이미지별 명세(지우기·배경 복원·글자·색·외곽선·글로우)를 `tools/imgedit.py`로 적용. 대부분 아틀라스라 조각별 원래 영역 안에서만 교체했습니다.
- 같은 그림이 여러 팩에 복제되어 있으므로 원본 텍스처 바이트 MD5 표(`tools/texhash.py`)로 모든 사본에 교체를 전파합니다.

## 업데이트 v1.1.0
- 업데이트 CIA(타이틀 0004000E00146C00)는 새 `.code`와 RomFS 41개 파일(이벤트 팩 6개, MainEventMess0202, 히어로 180·190 그래픽)만 담고 있습니다. 설치하면 이 파일들이 본편보다 우선합니다.
- 바뀐 대사는 원문 오타 수정(「しっかしろ」→「しっかりしろ」)뿐이라 기존 번역을 대응시켰습니다. 180·190 이름판은 그림이 바뀌어 따로 편집했습니다.
- `tools/mkupdate.py`: 업데이트 RomFS를 본편과 같은 글리프 표로 한글화 → NCCH RomFS·헤더 재작성 → CIA의 TMD 콘텐츠 크기·SHA-256과 콘텐츠 정보 해시 갱신(서명은 갱신하지 않음).
- 업데이트 실행 코드는 타이틀 버전 「VER. 1. 1. 0」의 「.」을 글리프 1279번으로 직접 그립니다. 이 칸(과 699번 「．」)은 한글로 덮지 않습니다.

## 히어로 전기 래퍼 UI
- 타이틀 「히어로 전기」는 RomFS `herosenki/herosenki.bin`(내장 레트로 게임)을 돌리는 래퍼로, 게임이 APT DoApplicationJump로 자기 자신을 인자와 함께 다시 실행합니다. 에뮬레이터에서 ROM 파일을 직접 열면 설치된 본편(`title/00040000/00146c00/content/00000000.app`)이 없어 실패합니다(`tools/place_base.py`로 본편 NCCH를 그 경로에 두면 검증 가능).
- 아래 화면 메뉴·대화창 문구는 실행 코드 안 UTF-16(대화·안내)·UTF-8(버튼) 문자열이며 시스템 공용 폰트로 그려집니다. 일본판 시스템 폰트에 한글이 없어 영어로 바꿨습니다. `tools/codestr.py`가 각 문자열의 원래 자리(종료 문자 + 뒤 0 패딩) 안에서만 교체하고, 실행 코드는 비압축으로 다시 넣습니다(`tools/build.py` `rebuild_exefs`).

## 실기 (LayeredFS)
- Luma3DS는 `SD:/luma/titles/<타이틀 ID>/romfs/` 의 파일로 게임 RomFS 파일을, `code.bin`으로 실행 코드를 대체합니다. `code.bin`은 실행 중인 버전(본편 또는 업데이트 v1.1.0)과 같아야 합니다. 본편에서 바뀐 1,653개 파일과 한글 업데이트 RomFS 파일을 이 구조로 둡니다.
- 배포용 생성기(`tools/lfstool`, C#)는 사용자가 xdelta로 만든 한글 `.3ds`와 원본 `.3ds`의 RomFS를 비교해 바뀐 파일만 뽑고, 한글 업데이트 CIA가 있으면 그 RomFS 파일을 덮어씁니다(게임 데이터를 직접 배포하지 않기 위함).

## 검증 도구
- `tools/launch.py`, `tools/cap.py`, `tools/ctrlkey.py`, `tools/emu.py`, `tools/myproc.py`: 포터블 Azahar를 비활성 창으로 띄우고 창 메시지로 키 입력·스크린샷(Ctrl+P)을 보내 사용자 조작을 방해하지 않고 확인합니다. 종료는 실행 경로로 자기 프로세스만 찾아 처리합니다.
- Azahar 포터블은 한글이 들어간 경로에서 바로 종료되므로 ASCII 경로(정션 등)에서 실행합니다. 디스크 셰이더 캐시는 끕니다.
